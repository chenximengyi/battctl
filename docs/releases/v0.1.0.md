# v0.1.0 — 重建仓库后的首个公开版本

本项目在新身份下重建仓库并重新从 `0.1.0` 开始编号。除标识符与文档地址外，
行为与上一谱系末尾版本一致：保存一个目标 → 必要时正常重启 → 由 macOS 自行
充放电到目标附近并保持。没有后台充电守护进程、适配器切换或区间循环。

## 变更

- 运行标识改为 `com.chenxi.battctl`：目标元数据、可选记录器的 LaunchAgent
  标签、遗留守护进程检测均使用新标识。原始上限备份路径保持不变。
- `scripts/install.sh` 在安装前把旧标识下保存的目标复制到新路径，升级后
  `verify` 仍按原意图核验，不会退回默认 50%。
- 更新克隆与发布地址、下载包名、文档与 CLI 版本断言为 `0.1.0`。
- 写入前检查、命令契约、失败回滚与恢复语义未改动。

## 下载与安装

从本页附件下载 `battctl-v0.1.0-macos-arm64.tar.gz` 与 `SHA256SUMS`，放在同一
目录执行：

```sh
shasum -a 256 -c SHA256SUMS
tar -xzf battctl-v0.1.0-macos-arm64.tar.gz
cd battctl-v0.1.0-macos-arm64
sudo ./scripts/install.sh
battctl --version
```

安装到 `/Library/Application Support/battctl/battctl`，入口为
`/usr/local/bin/battctl`。安装保留原目标与备份，本身不改变充电设置。

从旧版本升级同样执行上述步骤：安装脚本会把旧标识下的目标文件复制到
`/Library/Preferences/com.chenxi.battctl.plist`，随后 `battctl verify` 会按
原目标核验；若提示不一致，按输出检查系统充电上限与校准状态。

安装包包含对应 Tag 的源码和 `SOURCE_COMMIT`。程序未做 Developer ID 签名或
公证；被系统阻止时可用包内源码执行 `make test` 后自行安装，不要关闭 Gatekeeper
或 SIP。

## 设置与确认

首次使用前，在系统设置启用原生充电上限并选择 80%，结束临时充满覆盖，停用
其他电池控制程序。然后执行：

```sh
sudo battctl hold 50
# 若提示策略尚未生效：保存工作，由你正常重启 Mac
battctl verify 50
battctl status
```

插电正常使用即可，不需要 CLI 常驻或压力测试耗电。`hold` 新目标保存成功、
等待重启时返回 0，含义只是保存成功；同一目标已登记但当次行为不符或未知时
返回 1。`verify` 仅在登记一致、接电且当次电池行为符合目标时返回 0。电量可能
正常小幅波动。

`battctl doctor --json` 用于排查冲突与有效策略。当前 `hold 80/85/90/95` 也走
保存路径，尚未按档位即时设置；100% 与临时充满请使用系统设置。

## 恢复与卸载

```sh
sudo battctl restore
# 仅在以前启用过记录器时执行；不要加 sudo
./scripts/record-test.sh stop
sudo ./scripts/uninstall.sh
```

`restore` 恢复首次备份的系统上限，未必是 80%；按输出确认是否生效。原备份位于
`/Library/Application Support/battctl-reboot-test/previous-limit`，不要手动删除。
恢复失败时保留程序与备份，按提示检查或正常重启。

## 校准与限制

系统可能偶尔充满以校准电量估算，此时登记目标仍是 50% 但不代表正在执行。
本版本无法直接识别校准（`system_override=unknown`），只报告观测到的不一致。
本机曾观察正常重启后恢复放电，但这不是通用保证。本版本不会强制结束校准、
自动重启、循环充放电或后台持续控制。

使用 Apple 私有接口与偏好，后续系统更新可能改变行为。单次成功不能证明长期
保持或深睡眠期间行为；适配器供电能力、临时充满与其他电池工具都会影响结果。
